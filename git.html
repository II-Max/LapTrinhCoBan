🔀 Git – Hệ Thống Quản Lý Phiên Bản

Nắm vững Git từ cài đặt đến branching, đủ để tự tin làm dự án thực tế.

1 Cài đặt & Cấu hình Git

Bắt đầu

Git là hệ thống quản lý phiên bản phân tán phổ biến nhất thế giới. Trước khi sử dụng, bạn cần tải và cài đặt Git trên máy tính.

Tải và cài đặt

Truy cập trang chủ git-scm.com và tải phiên bản phù hợp với hệ điều hành của bạn (Windows, macOS hoặc Linux). Trên Windows, trình cài đặt sẽ bao gồm cả Git Bash — một terminal giả lập Linux giúp bạn chạy các lệnh Git một cách dễ dàng.

Sau khi cài đặt xong, mở Terminal (hoặc Git Bash trên Windows) và chạy git --version để xác nhận Git đã được cài thành công.

Cấu hình ban đầu

Git cần biết bạn là ai trước khi ghi nhận các thay đổi. Hãy thiết lập tên và email — thông tin này sẽ được gắn vào mỗi commit bạn tạo ra.

Bash 
# Thiết lập tên người dùng
git config --global user.name "Tên Của Bạn"

# Thiết lập email
git config --global user.email "email@example.com"

# Đặt nhánh mặc định là "main" (thay vì "master")
git config --global init.defaultBranch main

# Xem toàn bộ cấu hình hiện tại
git config --list
💡
Cờ --global: Khi dùng --global, cấu hình sẽ được áp dụng cho tất cả các dự án Git trên máy tính của bạn. Nếu bạn muốn thiết lập riêng cho một dự án cụ thể, hãy bỏ cờ --global và chạy lệnh trong thư mục dự án đó. Cấu hình cục bộ (local) sẽ ghi đè cấu hình toàn cục (global).

2 Ba Trạng Thái Của Git (Working → Staging → Repository)

Lý thuyết

Để sử dụng Git hiệu quả, bạn cần hiểu rõ ba khu vực (area) mà file của bạn di chuyển qua. Đây là khái niệm cốt lõi nhất của Git.

Ba khu vực chính

Khu vực Tên tiếng Anh Mô tả Lệnh liên quan
📁 Thư mục làm việc Working Directory Nơi bạn trực tiếp chỉnh sửa, tạo mới hoặc xóa file. Đây là trạng thái "chưa được theo dõi" hoặc "đã thay đổi". git status
📋 Vùng chuẩn bị Staging Area (Index) Vùng trung gian — nơi bạn "đánh dấu" những thay đổi sẽ được đưa vào commit tiếp theo. Bạn có toàn quyền chọn file nào sẽ vào commit. git add
🗄️ Kho lưu trữ Local Repository Cơ sở dữ liệu lịch sử của dự án. Mỗi commit là một "ảnh chụp" (snapshot) vĩnh viễn mà bạn có thể quay lại bất kỳ lúc nào. git commit

Luồng di chuyển của file

Hãy hình dung quy trình như một dây chuyền sản xuất:

Sơ đồ 
  ┌──────────────┐     git add      ┌──────────────┐    git commit    ┌──────────────┐
  │   Working    │ ──────────────▶  │   Staging    │ ──────────────▶  │  Repository  │
  │  Directory   │                  │    Area      │                  │   (Local)    │
  └──────────────┘                  └──────────────┘                  └──────────────┘
     Chỉnh sửa file                 Chọn thay đổi                    Lưu vĩnh viễn

Bạn chỉnh sửa file trong Working Directory, dùng git add để đưa thay đổi vào Staging Area, rồi dùng git commit để ghi nhận chính thức vào Repository.

✅
Mẹo – Atomic Commits: Mỗi commit chỉ nên chứa một thay đổi logic duy nhất (ví dụ: sửa một bug, thêm một tính năng). Điều này giúp lịch sử dự án dễ đọc, dễ review và dễ hoàn tác khi cần. Tránh gộp nhiều thay đổi không liên quan vào cùng một commit.

3 Các Lệnh Cơ Bản Hàng Ngày

Thực hành

Dưới đây là 5 lệnh Git bạn sẽ dùng hầu như mỗi ngày. Hãy nắm vững chúng trước khi học thêm các lệnh nâng cao.

Bash 
# 1. Khởi tạo kho Git mới trong thư mục hiện tại
git init

# 2. Xem trạng thái hiện tại (file nào đã thay đổi, file nào đang ở staging)
git status

# 3. Đưa TẤT CẢ thay đổi vào Staging Area
git add .

# 4. Tạo commit với thông điệp mô tả
git commit -m "thêm trang chủ"

# 5. Xem lịch sử commit dạng ngắn gọn
git log --oneline

Giải thích chi tiết

git init — Tạo một kho Git trống (thư mục ẩn .git) trong thư mục hiện tại. Bạn chỉ cần chạy lệnh này một lần duy nhất khi bắt đầu dự án mới.

git status — "Kim chỉ nam" của bạn. Lệnh này cho biết file nào chưa được theo dõi (untracked), file nào đã thay đổi (modified), và file nào đang trong Staging Area (staged). Hãy chạy lệnh này thường xuyên để nắm rõ tình trạng dự án.

git add . — Dấu chấm (.) có nghĩa là "tất cả". Lệnh này đưa mọi thay đổi (file mới, file đã sửa, file đã xóa) vào Staging Area. Bạn cũng có thể chỉ định file cụ thể: git add index.html.

git commit -m "..." — Lưu một "ảnh chụp" (snapshot) của Staging Area vào lịch sử dự án. Cờ -m cho phép bạn viết thông điệp commit ngay trên dòng lệnh. Thông điệp nên ngắn gọn, rõ ràng và mô tả cái gì đã thay đổi.

git log --oneline — Hiển thị lịch sử commit dạng rút gọn, mỗi commit trên một dòng gồm mã hash ngắn và thông điệp. Rất hữu ích để nhanh chóng xem tổng quan lịch sử dự án.

4 Phân Nhánh (Branch) & Hợp Nhất (Merge)

Nâng cao

Branching (phân nhánh) là một trong những tính năng mạnh mẽ nhất của Git. Nó cho phép bạn tạo một "phiên bản song song" của dự án để phát triển tính năng mới, sửa bug hoặc thử nghiệm — mà không ảnh hưởng đến code chính.

Khái niệm

Hãy hình dung nhánh (branch) như một "nhánh cây" mọc ra từ thân chính. Bạn có thể làm việc trên nhánh riêng, và khi hoàn thành thì "ghép" (merge) nhánh đó trở lại nhánh chính (main).

  • Nhánh chính (main): Chứa code ổn định, đã được kiểm tra.
  • Nhánh tính năng (feature branch): Nơi phát triển tính năng mới, ví dụ feature/login, feature/cart.
  • Nhánh sửa lỗi (bugfix branch): Dùng để sửa bug khẩn cấp, ví dụ bugfix/header-overlap.

Các lệnh quản lý nhánh

Bash 
# Xem danh sách tất cả các nhánh (nhánh hiện tại có dấu *)
git branch

# Tạo nhánh mới VÀ chuyển sang nhánh đó ngay lập tức
git checkout -b feature/login

# Chuyển về nhánh main (lệnh mới, khuyến khích dùng)
git switch main

# Hợp nhất nhánh feature/login vào nhánh hiện tại (main)
git merge feature/login

# Xóa nhánh đã merge xong (dọn dẹp)
git branch -d feature/login

Quy trình làm việc với nhánh

  1. Đang ở nhánh main, tạo nhánh mới: git checkout -b feature/login
  2. Viết code, commit nhiều lần trên nhánh feature/login
  3. Khi hoàn thành, chuyển về main: git switch main
  4. Merge nhánh tính năng vào: git merge feature/login
  5. Xóa nhánh cũ: git branch -d feature/login
⚠️
Merge Conflicts (Xung đột hợp nhất): Khi hai nhánh cùng chỉnh sửa cùng một dòng trong cùng một file, Git không thể tự quyết định giữ phiên bản nào và sẽ báo conflict. Bạn cần mở file bị xung đột, chọn giữ đoạn code nào (hoặc kết hợp cả hai), sau đó git add và git commit để hoàn tất quá trình merge. Đừng hoảng sợ — conflict là chuyện bình thường!
